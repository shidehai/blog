# 自建单作者发帖与内容管理后台

## Goal

为现有 Blog 自建专用发帖与内容管理后台，替换 Directus，让作者直接控制写作界面、内容字段和发布流程。正文保持可移植的 Markdown，历史内容和媒体可恢复、可导出。

## Confirmed User Decisions

- 2026-10-14：用户明确不再使用 Directus，希望自建发帖与内容管理平台；原因是现有平台的限制和定制需求。
- 2026-10-14：用户选择「Markdown 编辑＋实时预览」。
- 2026-10-14：用户明确「一直都只会是我一个人使用」。永久单作者是产品边界，不为未来多人使用预留角色、团队或审批模型。
- 2026-10-14：用户明确「点击发布后直接更新博客」，内容上线不等待整站构建、部署或进程重启。
- 2026-10-14：用户要求本项目仅允许主会话执行，包含主会话的 AI 并发数为 1；禁止子代理、外部 AI worker 和委派其他会话。
- 2026-10-14：用户强调后台「要做得美观好看」，并确认关心文章插图能力；图片属于首版写作体验。
- 2026-10-15：用户批准切换并澄清尚未远程部署，当前目标是本地项目切换；接受已列明旧历史保留原始档案的处置。

## Requirements — Confirmed Implementation Scope

- R1：正常写作、管理和发布不再依赖 Directus 服务、SDK、权限授权或管理界面。
- R2：正文以 Markdown 编辑和存储，提供实时预览。预览与公开页面使用相同的语法规则和文章排版。
- R3：只支持一个所有者账号，不开放注册，不引入多作者、团队、角色权限矩阵或审批流。
- R4：所有者可登录、退出并通过受控的本机管理方式恢复访问。后台页面、写入接口和草稿媒体均需要认证；公开读者无需登录。
- R5：支持文章的新建、搜索、编辑、归档和恢复，管理标题、摘要、固定地址、封面、分类、标签、系列及现有文章类型。迁移后保留已发布文章地址和发布时间。
- R6：编辑器支持自动保存并明确显示保存中、已保存和失败状态；刷新后能恢复最后成功保存的草稿。单作者的多标签页编辑仍须识别过期写入，不能静默覆盖较新的内容。
- R7：工作草稿与已发布版本分离。编辑或恢复草稿不会改变线上内容；发布是显式操作，原子切换已发布版本并确认结果，失败可重试。归档后新请求不再读到该内容。
- R8：支持通过上传按钮、拖拽文件、粘贴截图和从媒体库选择插入正文图片，自动生成 Markdown 并实时预览，无需手动填写图片地址；支持替代文本、封面设置和媒体引用查看。上传过程显示进度，失败可重试；未发布内容的私有素材不得通过公开读取接口暴露；媒体原文件和元数据均纳入备份。
- R9：保存可恢复的历史版本，支持查看并恢复为工作草稿。迁移盘点须覆盖 Directus versions、revisions、正文、关系和媒体，说明任何无法等价恢复的历史记录。
- R10：支持分类、标签、系列和站点资料管理；保留既有随记、专题及其关系。此任务不自动增加随记或专题的公开路由。
- R11：提供结构化内容与媒体导出及备份恢复流程，迁移可重复核验。只有在内容、地址、媒体和恢复能力核对通过后才切换正式写入来源。
- R12：后台界面、字段校验和业务流程由本仓库代码控制；使用成熟基础组件，并审查新依赖的许可与部署要求。
- R13：后台支持键盘操作、明确焦点和可理解的错误反馈；预览、保存、发布状态不能只靠颜色区分。
- R14：点击发布成功后，公开站的新请求立即读取该次发布的内容，新增地址也能直接访问；文章、分类/系列导航和搜索结果同步反映发布状态，无需重新构建、部署或重启。已有打开页面在刷新或导航重新读取后更新，不要求向读者持续推送。
- R15：所有研究、规划、实现、审查、测试和收尾由主会话串行执行，遵循根目录 AGENTS.md 的硬性限制。
- R16：后台美观好看是首版验收要求。围绕写作建立统一的字体、配色、间距、控件和状态反馈；宽屏提供舒适的编辑/预览布局，小屏保留清晰的操作层级，图片和封面展示协调。视觉方向与博客现有身份一致，细节在实际页面中核验。

## Acceptance Criteria

- [x] AC1（R1、R3、R4）：停用 Directus 后，唯一所有者仍可登录并完成编辑、媒体管理和发布；不存在公开注册或未认证写入入口。
- [x] AC2（R2、R6、R13）：包含中文、代码块、图片、列表和表格的 Markdown 能编辑并实时预览；保存状态清晰，刷新可恢复已保存草稿，多标签页的过期保存会被拒绝或显式提示。
- [x] AC3（R7、R9、R14）：修改已发布文章或恢复历史版本时，线上仍展示原已发布内容；显式发布后新请求立即读取新版本，失败不会显示为已上线；归档后正文不再公开，失去所有公开引用的媒体停止开放。
- [ ] AC4（R8）：上传、拖拽、粘贴截图和媒体库选择均能在光标位置插图、自动生成有效 Markdown，并在预览与发布页显示同一图片；图片比例正确且不撑破窄屏，可设置替代文本及封面。上传进度可见、失败可重试；未认证访问无法读取私有草稿媒体，备份包含实际媒体文件。
- [x] AC5（R5、R9、R10、R11）：迁移报告逐项核对内容类型、数量、稳定标识、文章地址、时间、关系、媒体校验和及版本历史；源数据保持可恢复，任何迁移差异明确列出。
- [x] AC6（R10）：作者可管理分类、标签、系列和站点资料；现有随记、专题及关系可在新系统中保存和管理，公开路由仍遵循已确认范围。
- [x] AC7（R11）：在隔离环境完成一次内容和媒体的备份恢复演练，恢复结果可与导出清单比对。
- [x] AC8（R12）：新增文章字段或后台行为可以通过本仓库的代码及数据库迁移实现，不要求 Directus 授权或修改上游 CMS。
- [x] AC9（R14）：在已构建并启动的生产进程上新建并发布一个从未构建过、且此前访问为 404 的地址，文章详情、列表、分类/系列导航和搜索均可读到新内容；验证更新、归档、预取、前进/后退及重新聚焦时的内容刷新，期间没有构建、部署、服务重启或发布 webhook。2026-10-15 补齐真实 focus/visibility 与 RSC transport，Link 自动预取禁用，不宣称已填充客户端预取缓存。
- [x] AC10（R15）：执行期间只存在主会话，没有子代理、AI worker 或其他受委派会话；Trellis 使用 inline 模式，Codex 项目配置禁用子代理，工具调用串行执行。
- [x] AC11（R13、R16）：使用真实长标题、中文正文、横/竖图和有/无封面文章，核验内容列表、编辑器和媒体库在桌面及手机上的视觉效果；字号、间距、控件和配色统一，无横向溢出或操作遮挡。正常、空内容、上传中、保存失败与发布成功状态均有完整设计，并向用户展示实际界面供审阅。

## Scope Boundaries

- 第一版聚焦个人写作、内容管理、媒体、历史恢复、发布及迁移。
- 永久不包含多人协作、注册、角色矩阵、团队和审批流。
- 第一版暂不包含评论社交、可视化页面搭建器、通用模型搭建器、AI 写作、定时发布、统计分析或新的公共内容频道；如用户提出需求，再重新确认范围。

## Technical Notes and Operational Trade-off

- 技术边界、数据契约、媒体交付、迁移和回退方案见 design.md；串行执行顺序及验收见 implement.md，现有代码核验见 research/cms-replacement.md。
- 即时发布将公开阅读改为依赖内容服务和数据库在线。首版不引入跨请求内容缓存或队列；服务故障应明确返回不可用，不把旧内容或离线夹具伪装成当前线上内容。代码更新仍走正常构建和部署流程。
- 实际草稿、历史修订和媒体的完整性必须通过源快照盘点及恢复演练验证，不能仅根据仓库文件宣称已完成无损迁移。
