# 自建单作者 CMS 技术设计

状态：已按用户批准完成本地实现、核验及日常写入来源切换。用户明确尚未远程部署，本轮范围仅为本机。约束来自 prd.md 中 R1—R16；研究依据见 research/cms-replacement.md。全程仅主会话串行执行。

## 架构与所有权

沿用现有 TypeScript、Next.js 和 PostgreSQL 技术栈，增加独立的 `author-cms/` 应用。它负责唯一所有者的认证、内容编辑、发布、历史、媒体和数据导出。公开站仍在 `frontend-v2/`，通过受限的服务端发布读取接口取得内容，不直接连接数据库。后台界面和业务字段由本仓库控制，不依赖通用 CMS 的模型和权限产品。

| 边界 | 所有权与约束 |
| --- | --- |
| `author-cms/` | Next.js 管理界面、私有写入接口、发布读取接口、数据访问和数据库迁移 |
| `packages/content-contracts/` | Zod 请求/响应契约、公开摘要与详情类型；不包含服务端凭据或数据库连接 |
| `packages/markdown/` | 前台与预览共用的 Markdown 处理、目录、图片语义和文章排版 |
| PostgreSQL `author_cms` schema | 唯一实时内容权威；新表与旧 Directus 表隔离，由显式 SQL 迁移控制 |
| CMS 持久媒体目录 | 原文件、校验和及必要的安全显示副本；不写入站点镜像或 Git |
| Compose / Caddy / operations | 服务连接、运行时秘密、域名、媒体交付、健康检查、备份及恢复 |

CMS 使用 Drizzle + pg 访问自己的表。依赖引入前锁定兼容现有 Node 24、React 19 和工具链的正式版本并复核许可证。首版不增加 Redis、消息队列、对象存储或独立搜索服务；保留自托管持久文件与 Restic 备份方式。

## 单作者写作体验

后台按内容列表、编辑器、媒体、分类/标签/系列和站点资料组织。文章编辑器在宽屏并排呈现 Markdown 与预览，小屏切换编辑/预览。使用 CodeMirror 6 处理 Markdown 输入和键盘操作，实时预览共用公开正文渲染器；标题、摘要、地址、分类、标签、系列与封面集中在文章属性区域。

### 视觉方向与验收

用户明确要求美观好看，将其作为首版交付要求。后台以专注写作的工作台组织信息：窄侧栏用于切换内容和媒体，主区域以文章标题与编辑/预览为中心，顶部清晰呈现保存状态和发布动作，文章属性按需展开。内容列表采用有明确文字层级与封面缩略图的行布局，媒体库以图片缩略图方便识别和选择。

视觉以中性色背景、清晰文字、充足留白和少量强调色建立质感；采用统一的按钮、输入框、图标、焦点和短促状态过渡。沿用当前博客实际 CSS 的色彩语义和中英文排版作为身份依据；DESIGN.md 的种子意图与实际样式存在差异，本次只记录新后台方向，不顺带更改全站设计系统。编辑文字与预览正文保持舒适行宽，长内容不挤压发布操作，媒体比例与文章布局协调。

用真实中文长标题、代码、横竖图片和有/无封面内容核验桌面与手机布局，检查空内容、上传、保存失败和发布成功状态。视觉审阅及修正全部由主会话串行执行，交付时展示实际界面，不将技术检查通过等同于视觉效果已经验收。

自动保存显示保存中、已保存和保存失败；发布前先等待当前草稿成功保存，发布请求指定确切的草稿版本。失败保留编辑内容，离开页面时对未保存改动提示。单作者的多个标签页通过乐观锁识别过期编辑，并提供重新载入或另存草稿的明确操作，不静默覆盖。

“保存草稿”和“发布”是不同动作。已发布文章继续编辑、恢复历史或更换草稿封面都不会影响线上；发布成功后显示文章地址与“查看文章”。归档是明确撤回动作。站点资料及分类定义的按钮说明其保存会更新公开展示，文章草稿中的分类关系仍在发布时生效。随记与专题可管理和迁移，但首版不增加它们的公开频道，也不把后台保存成功描述为新增公开路由上线。

## 数据模型与状态

| 数据 | 核心职责 |
| --- | --- |
| `owner` / `sessions` | 唯一所有者及可撤销会话；数据库约束阻止第二个所有者，无注册和角色表 |
| `contents` | 稳定 ID、类型、当前草稿版本、当前已发布版本、归档状态和乐观锁版本 |
| `content_revisions` | 不可变的正文与属性快照，保存来源、时间、内容摘要及类型化关系 |
| `taxonomies` / `site_profile` | 分类、标签、系列和站点资料；显式保存后更新公开配置版本 |
| `slug_aliases` | 历史公开地址到内容 ID 的映射；发布改址时创建，避免地址丢失和跳转链 |
| `media` / `published_media_refs` | 受控文件键、类型、大小、校验和、源隐私标记及当前公开引用 |
| `publication_requests` / `public_state` | 发布幂等键与结果，以及单调递增的公开内容 generation |
| `migration_mappings` | 旧 ID、版本、文件、目标 ID 与迁移批次的可核对对应 |

正文始终是 Markdown，不使用编辑器私有 JSON 作为权威格式。每次成功保存创建不可变修订并更新草稿指针；相同内容去重、输入防抖，首版不自动清理历史。恢复历史会生成新的工作草稿，不改变已发布指针。

修订记录包含该版本的标题、地址、摘要、正文、封面与分类/标签/系列关系，禁止发布读取把新的草稿字段拼接到旧正文上。公开分类名称来自已显式保存的分类定义，分类计数及成员关系仅从当前已发布 article/tutorial 计算。随记、专题、未发布版本和无已发布引用的分类不进入公开目录。

地址在保存和发布时校验；当前地址及历史别名统一检查冲突。已发布文章改址时在同一事务中更新规范地址并将旧地址绑定到内容 ID；旧地址直接跳到当前规范地址。归档保留地址占用和历史，恢复到草稿不会自动重新上线。

## 保存、发布与失败契约

私有保存接口接收预期版本，成功返回新 revision ID 与版本；过期写入返回 409 及可恢复提示。私有接口统一采用服务端校验，浏览器显示的状态不是权限依据。

发布接收 content ID、预期版本、待发布 revision ID 和幂等键。在一个数据库事务内锁定内容行，核验版本、地址、必填字段、关系与媒体完整性，切换已发布指针，更新公开媒体引用，递增 generation 并记录发布结果。媒体文件必须先完成持久化和校验，不在事务提交后才开始复制必需文件。

只有提交成功才返回“已发布”。同一幂等键重试返回同一发布结果；网络超时导致结果不明时通过该键查询，避免把已提交误报为未发布或重复发布。保存冲突、媒体缺失或数据库失败均不产生部分上线状态。归档同样原子移除公开状态、媒体引用并递增 generation。

发布成功意味着提交后的公开新请求读取新版本；不等待镜像构建、部署、重启、webhook 或后台任务。已在读者浏览器中显示的页面在刷新、导航或重新聚焦时重新校验，不要求持续推送。

## 公开读取与即时更新

| 契约 | 返回内容与行为 |
| --- | --- |
| 内网发布目录 | generation、站点资料、PostSummary 列表和已发布分类/系列；不包含全部正文 |
| 内网文章详情 | 当前已发布快照、规范地址、目录/导航需要的摘要；不存在返回 404，服务不可用返回 503 |
| 公开媒体读取 | 仅允许具有当前发布引用且可公开的媒体；私有原文件不通过静态目录直出 |
| 私有编辑/版本/媒体接口 | 每次校验所有者会话，不复用公开目录的权限判断 |

内网发布接口只接受独立的服务读取凭据，且查询硬编码为发布投影；该凭据没有私有草稿或写入权限。前台只在服务器运行时使用凭据，不把它传入浏览器、构建参数、日志或镜像。CMS 的数据库角色不读取 Directus 系统表；迁移身份单独管理。

替换 `frontend-v2/lib/content.ts:23` 的进程级 Promise 缓存。读取使用 no-store，内容路由动态渲染；同请求可用 React cache 去重，禁止模块单例或跨请求缓存发布内容。目录/详情在数据库事务的一致快照中组装，单篇 metadata 与正文共用同一次详情读取，避免混用版本。

移除文章、旧 writing 地址、分类与系列的构建期 slug 限制；不再依赖 generateStaticParams 覆盖所有文章。保留 `/archives` 及详情规范地址，`/writing/[slug]` 对可公开文章永久跳转到规范地址，`/writing`、未知内容和 `/notes/*` 维持现有公开范围。

根 layout 不保留全站正文或永久内容快照；将搜索、侧栏和目录需要的数据收敛为 PostSummary，并置于能重新读取的内容边界。对内容链接关闭提前预取，导航、前进/后退及重新聚焦时使用 no-store generation 校验，版本变化后触发受控刷新；避免每次刷新都重复触发刷新。验收必须包含曾经预取的文章和曾返回 404 的新地址。

内容 HTML、RSC、公开读取和受权限控制的媒体响应不使用持久共享缓存，Caddy 同步配置；只有带内容指纹的代码静态资源长期缓存。上传媒体改为运行时交付，移除构建时物化媒体的生产依赖。源不可用时明确报错，不回退 fixture，不把故障转成内容不存在，也不继续返回可能已撤回的旧快照。

## Markdown 与媒体

提取现有 MarkdownContent、目录、图片映射及文章样式为共享能力，使用统一的 GFM、代码块和允许列表 HTML 清理规则。迁移前为现有正文建立中文、代码、图片、表格、链接和目录样本；预览与公开页面必须产生相同的文章内容和排版。草稿预览媒体走已认证的后台接口，公开版本映射到受控的公开媒体地址。

编辑器提供上传按钮、拖拽图片、粘贴截图及从媒体库选图四个入口。上传记录插入位置并显示进度，成功后在对应位置生成标准 Markdown 图片引用；作者可以编辑替代文本，并继续输入正文。失败时保留可重试的提示，不写入不可用的临时图片地址；存在未完成或失败的待插入图片时，发布操作明确提示先完成处理。媒体库可重复选用已有图片，封面选择单独显示裁切预览。

正文图片保持原始比例、随容器缩放，长图和竖图不撑破页面；正文预览与公开文章使用一致的图片排版。封面缩略图可以按卡片比例裁切，但不将该裁切应用到正文原图。图片管理与写作衔接，不要求作者复制文件地址或手工编写插图语法。

上传校验实际文件类型、大小和文件键，使用临时文件、校验和及原子落盘；数据库只保存受控存储键，禁止任意路径访问。保留原文件，SVG 等可执行格式采用安全显示副本或受限下载，不能仅按扩展名当作可信图片。文件默认私有，普通新上传素材在显式发布时按引用公开；源库明确标记私有的素材必须单独处理，不能因引用被自动公开。

公开媒体引用包含当前已发布正文、封面及显式公开的站点资料。文章换图或归档后，失去所有公开引用的媒体在新请求中停止公开；后台历史恢复仍可访问其原文件。媒体删除先归档或标记，不删除仍被历史引用的原文件，首版不自动做物理垃圾回收。

## 认证与部署

唯一所有者通过受控本机命令初始化和重置密码，不提供注册、邮件服务或团队权限配置。密码使用 Node 异步 scrypt 和独立随机盐，参数及并发预算在实施时验证；会话令牌只在 HttpOnly、Secure、SameSite cookie 中传输，服务端保存令牌摘要，退出及重置密码可撤销会话。登录限速、请求来源/CSRF 校验和秘密脱敏属于认证边界。

Compose 增加 CMS 服务并沿用 PostgreSQL、Caddy 和持久存储。SITE_DOMAIN 仍提供博客，CMS_DOMAIN 切到独立后台；公开媒体通过博客同源受控路径代理，不把 CMS 的私有接口整体暴露在博客域名。镜像保持非 root、健康检查和资源上限；数据库及内容凭据只在必要服务的运行时注入。

删除内容发布触发整站镜像构建的依赖。代码变化继续经过 CI 验证、镜像构建和正常部署；更新 CI、镜像检查与运维脚本，使构建无需在线 CMS，运行时凭据不进入镜像。旧的“运行时完全无内容配置”测试替换为新的秘密和发布读取边界测试，不能只删除安全检查。

## 迁移、导出与回退

1. 先对只读源快照生成清单：文章类型、稳定 ID、正文、地址、时间、分类关系、作者资料、文件校验和、versions 和 revisions。确认未绑定 item 的版本草稿及 delta 历史可重建性；未知形态必须报告，不能静默跳过。
2. 在隔离数据库的新 schema 和新媒体目录导入，保留旧库与原始文件。迁移批次和 ID 映射支持重复核验及中断后恢复，不覆盖已有作者写入。
3. 将可重建修订转成不可变版本；无法等价重建的记录保留受保护的原始档案，并在报告中逐项列明，迁移验收前不宣称无损。公开内容、关系、时间、地址、媒体和草稿逐项对账。
4. 内容导出包含版本化 JSON、Markdown、关系、媒体与校验清单，排除密码和会话。原始系统数据库备份包含敏感数据，独立保存在受保护的加密备份中，不混入浏览器内容导出。
5. 先完成备份恢复演练和生产模式验证，再短暂停止旧后台写入、取最终一致快照、补齐差异并切换。切换后只保留一个编辑来源；旧 Directus 可作为恢复资料保留，正常运行不依赖它。
6. 新后台还未接受写入时可恢复旧路由和只读源；已经产生新写入后不能简单回退到旧数据库快照。先冻结写入、保存新数据与媒体，优先修复或恢复新系统，防止回退丢失切换后的内容。

2026-10-15 本地切换后按作者要求移除旧运行工具与服务。当前备份格式 2 覆盖数据库与 CMS 媒体（含 originals），无需旧 uploads；含完整 CMS 媒体的过渡格式 1 可恢复。源快照、旧数据库和媒体备份独立保留，离线转换器仍用于隔离恢复。恢复在隔离目标演练并比对清单。内容服务和数据库成为公开阅读依赖，需要有限超时、明确 503、健康检查与恢复流程。首版接受这一运行取舍，后续仅在实际性能证据出现时再设计缓存。

## 规范与实施边界

PRODUCT.md、README、现有 frontend/backend specs 和运维手册中以 Directus 与静态快照为前提的条款必须随实施更新，保留单一内容权威、秘密隔离、草稿隐私和数据可恢复的目标。此次规划不重写全站视觉系统、不增添多人协作、审批、通用模型搭建、评论、AI 写作或新的公共频道。

现有任务、用户日志和未跟踪的 SVG 均不属于本次产品改动；不覆盖或顺带提交。所有实现与验证由主会话依次进行，任何默认派发代理的说明都服从 AGENTS.md。

## 实现核验补充（2026-10-14）

- 当前实现与工具入口见 author-cms/README.md、docs/authoring.md 和 operations 手册；准确依赖许可见 author-cms/DEPENDENCIES.md。
- generation 改变时浏览器执行 document reload。实际浏览器发现 router.refresh 会保留旧 404 边界，修复后已验证返回原 404 地址显示完整正文及前进归档更新。
- 已预建 schema 的受限角色不能执行 CREATE SCHEMA IF NOT EXISTS；迁移先查询 pg_namespace，仅在缺失时建 schema。初始 SQL 不重复创建。受限角色镜像烟测已通过并证明不能读旧表。
- 媒体使用不可变原子落盘并 fsync；发布锁定媒体行，隐私修改递增 generation。发布结果未知时保留同一 key 并锁定编辑直至确认。
- 续轮补回 5 个已删除专题至归档，历史关系只接受独立完整快照，拒绝借用当前值。最新报告有 68 项限制（64 条修订＋4 条缺原快照的删除活动）；源档案可完整导出恢复，不代表所有历史均可等价恢复。见 acceptance.md 和 cutover-review.md。
