# 简化 VPS 部署 — 2026-10-15

用户认为首次部署步骤过多，要求常规 docker-compose.yml 方式。继续当前已激活任务，主会话串行实现；现有本机内容、账号、配置及无关改动保持原样。

## 目标与边界

- 根目录提供 Docker Compose 默认入口，复用 deploy/compose.yaml 的生产拓扑；只在独立 override 中增加源码构建和新 PostgreSQL 的受限角色初始化。
- 首次运行 scripts/setup-vps.sh，只输入博客域名、后台域名、邮箱。脚本生成受保护的 .env、随机后台密码、持久目录，依次构建两镜像并固定实际 image ID，自动执行迁移、只初始化不存在的所有者，启动服务。
- 可选 --import DIR 调用既有完整内容包 verify/restore，复制输入到私有临时挂载，不修改原包；拒绝覆盖已有内容。重复执行保留既有凭据与所有者，会话不会被重置。
- 日常使用 docker compose up -d / ps / logs / down。Docker 与域名解析是宿主机前置条件；HTTPS、异机备份与真实 VPS 验收仍单独确认。
- 不改应用、数据模型或既有迁移文件，不自动操作日常本机环境或连接 VPS。

## 实现与验证计划

1. 新增根入口、standalone override、PostgreSQL 一次性初始化脚本和 setup-vps.sh；更新默认入口指南。
2. 为未知 .env/非空新目标拒绝、秘密与权限、失败后重试、所有者保留及导入幂等标记添加运维回归。
3. 渲染根/原生产/开发/本地 Compose，复查持久路径、只读/非 root 与唯一公网入口。standalone 检查允许本地不可变 image ID，自动发布继续要求 registry digest。
4. 用既有验证镜像及独立数据库/媒体目录完整跑初始化和重复执行；验证角色权限、账号、文章发布和内容恢复，不占用日常端口。
5. 运行项目质量门禁，保存证据，按既有提交推送授权交付当前分支；不部署远程服务器。
